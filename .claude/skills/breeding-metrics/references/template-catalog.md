# 템플릿 카탈로그(백로그)

사용자가 구체적인 템플릿을 지정하지 않고 "다양하게", "기본 세트"를 요청하면 여기서 고른다. `slug`는 폴더 이름이며 kebab-case다. 상태는 오케스트레이터가 `src/templates/` 폴더를 보고 판단하므로 이 문서에 적지 않는다.

## 배치 구성 기본값

- 기본 배치는 2개다. 아직 없는 항목 가운데 우선순위 숫자가 가장 작은 것부터 카테고리가 겹치지 않게 고른다.
- "카테고리마다 하나씩"이면 카테고리별로 남은 항목 가운데 우선순위가 가장 높은 것 하나씩.
- "전체", "모두"면 남은 항목 가운데 가장 높은 우선순위 전체를 먼저 하고, 다음 우선순위는 다음 배치로 제안한다.
- 남은 항목이 없으면 아래 「확장 후보 기준」으로 확장 절을 새로 만든다(오케스트레이터 「카탈로그 확장」).

## 확장 후보 기준

분석가가 「확장 N」 후보 6~8개를 제안할 때 따른다. 확장 1·2가 이 기준으로 만들어졌다.

1. **같은 가상 프로그램의 사실을 다룬다.** `program-baseline.md`에 있지만 아직 어느 템플릿도 주 화면으로 다루지 않는 사실을 우선한다. 기존 기준값을 그대로 쓰면 템플릿 사이 숫자가 저절로 맞는다.
2. **기존 템플릿과 핵심 질문이 겹치지 않는다.** 같은 데이터를 다른 차트로만 보여 주는 후보는 넣지 않는다. 겹칠 것 같으면 어느 템플릿과 무엇이 다른지 한 줄로 밝힌다.
3. **실제 육종 업무나 의사결정 단계에 대응한다.** 사용자(육종가, 분석실, 연구 관리자, 품종 보급 담당)와 사용 시나리오를 한 줄로 적을 수 있어야 한다.
4. **카테고리 분포를 맞춘다.** 지금 템플릿이 적은 카테고리부터 채운다. 한 확장에 업무 화면과 인포그래픽이 적어도 하나씩 들어가게 한다.
5. **새로 정해야 할 기준값을 적는다.** baseline에 없는 숫자가 많이 필요한 후보는 그 목록을 쓴다. 명세 단계에서 baseline에 추가할 항목이 되고, 너무 많으면 우선순위를 낮춘다.
6. **브리프에는 화면 목적과 범위만 쓴다.** 숫자는 baseline에서 읽게 한다(2단계 원칙과 같다).
7. **우선순위는 두 단계로 나눈다.** 확장 N은 P(2N+2)(먼저 만들 것)와 P(2N+3)을 쓴다.
