# 시각 언어

## 방향

- **연구 도구의 정밀함**: 중립 회색 계열 배경(따뜻하지도 차갑지도 않은 약간의 청회색), 얇은 1px 경계, 그림자는 최소. 정보 밀도가 높은 화면이 기본이다.
- **강조색은 하나**: 예) 깊은 청록(teal) 또는 인디고 계열 하나를 `--color-accent`로. 녹색 계열은 "증가·통과" 의미색과 혼동되므로 강조색으로 쓰지 않는다.
- **데이터가 주인공**: UI 크롬(버튼, 탭, 경계)은 저채도, 데이터 마크만 채도를 가진다.

## 색

- 범주형 8색: 색상환에서 고르게 떨어뜨리고, 인접 색끼리 명도 차를 둔다. 첫 3색만으로도 구분되게 한다(대부분 차트가 3계열 이하).
- 순차형: 밝은 → 진한 단일 색상 7단계(히트맵, r², 밀도). 다크 모드에서는 순서를 뒤집지 말고 배경 대비만 조정한다.
- 발산형: 음(파랑 계열) — 중립(배경에 가까운 회색) — 양(주황·빨강 계열). 상관 행렬, GEBV 편차.
- 의미색: positive/negative/warning/info. 증감 표시에는 색과 함께 ▲▼ 기호를 쓴다.
- 유전체 교대색(`--viz-chr-a/b`)은 채도가 낮은 슬레이트 2단(진/밝)으로 둔다. 리드 SNP·선택 표시는 `--color-accent`로 칠하므로, 배경 점과 강조가 색상(채도)만으로도 구분돼야 한다. 강조색이나 `--viz-cat-1`과 같은 색상 계열을 염색체색으로 쓰지 않는다.
- 의미색 negative·warning(라이트)은 Badge(의미색 10% 배경 위 12px 글자)가 bg·surface·surface-2 위 모두 4.5:1 이상이 되게 정했다(warning #975200, negative #b52e1c). 값을 바꾸면 이 조건을 다시 계산한다.
- 대비: 본문 텍스트 4.5:1 이상, 큰 숫자·차트 마크 3:1 이상(라이트·다크 모두).
- **색 검산 스크립트**: 토큰 색을 바꿀 때는 `node .claude/skills/db-design-system/scripts/check-palette.mjs --set dark:--viz-cat-2=#…`로 전·후를 비교하고, 반영한 뒤 인자 없이 다시 실행해 위반 0건을 확인한다. 기준: 바꾼 색의 surface·bg 대비 3:1, 다크 cat-2 ↔ warning·cat-3 ↔ positive ΔE00 ≥ 15, 첫 3색이 정상·적색맹·녹색맹 시뮬레이션 모두 ΔE00 ≥ 12, 바꾼 색과 다른 범주색·의미색·강조색 ΔE00 ≥ 15, 범주색 쌍 최솟값이 줄지 않음. 바꾸지 않은 라이트 cat-2·cat-5·cat-6의 bg 대비 3:1 미달(2.1~2.8)은 팔레트 유지 결정에 따라 '참고'로만 보인다.

### 강조색은 데이터와 선택 표시에만(앱 화면 규칙, 2026-10-30 사용자 결정)

| 자리 | 쓰는 색 |
| --- | --- |
| 주 버튼(`Button primary`, SaveBar 저장) | `--color-primary` 거의 검정 채움(라이트 #1d1f20 + 흰 글자 16.6:1, 다크 흰 채움 + #0e1116 글자 18.9:1) |
| 크롬 활성(FilterChip 켜짐, Stepper 현재 번호) | `--color-active` 회색 채움(라이트 #e2e5ea, 다크 #2f3540) + 잉크 글자 |
| Tabs·Stepper 현재 | 잉크 글자 + 2px 잉크 밑줄 |
| Segmented 선택 | 회색 트랙 위 흰 칸 + 1px `outline-border`(그림자 없음 — 버튼에 그림자는 tasteskill button-fx FAIL, 2026-10-31) |

템플릿이 직접 만든 크롬(범례 토글, 직접 만든 탭·칩·확정 버튼)도 같은 규칙을 따른다. `bg-accent text-accent-contrast` 채움 버튼·칩은 `Button primary`나 회색 채움으로 옮긴다.

### 데이터 위 선택 표시 = 글자색 테두리 + 표면색 후광

히트맵 셀, 산점도 점, 순위표 칸, 격자 칸처럼 **데이터 색 위에서** 선택·현재 항목·1위를 표시할 때는 강조색이 아니라 글자색(`--color-text`) 테두리를 쓰고, 그 밑에 표면색(`--color-surface`) 후광을 깐다. 강조색은 범주 1색·순차 척도(파랑)와 사실상 같은 색이라 데이터에 묻힌다. 기준 구현: `viz/trait-correlation` CorrelationMatrix 선택 셀.

| 매체 | 규격 |
| --- | --- |
| SVG·ECharts graphic | 같은 도형을 두 번: 표면색 선 4px(후광) → 글자색 선 2.5px. `selectionStroke(theme)`(@/charts)이 두 값을 준다 |
| ECharts 산점·기호 | 선택 점 자리에 빈 고리 두 개(후광 → 선): `selectionSymbolSeries(theme, { value, symbol })`(@/charts, 2026-10-30 C단계). 점 테두리만 글자색으로 바꾸거나 `shadowBlur`로 후광을 흉내 내지 않는다 |
| HTML 칸·카드 | `select-ring` 클래스(글자색 2.5px 안쪽 테두리 + 표면색 1.5px 안쪽 후광) |
| 표 행 | `DataTable` `activeRow`(2px 글자색 윤곽, 고정 열 위에서도 이어짐) |

- 군집 경계·그룹 상자 같은 **구조선은 선택과 같은 모양으로 그리지 않는다**(muted 1.5px 또는 점선).
- 강조색은 UI 크롬(Segmented·FilterChip 켜짐, 탭 밑줄, 대표 KPI 타일)에 쓰지 않는다. 크롬 선택은 위 「자리별 색」 표(회색 채움·잉크 밑줄·흰 칸 + 테두리)를 따른다(T7, 2026-10-30). `select-ring`의 안쪽 그림자는 선택 표시 자체라 버튼 그림자 규칙의 예외다.

### 강조색·정보색

- `--color-accent`와 `--color-info`(라이트 ΔE 8.0)는 **한 그림 안에서 서로 다른 계열로 쓰지 않는다**(예: 생키의 '진급'과 '출원 예정'). 둘째 계열은 다른 범주색이나 점선·빗금 같은 모양으로 구분한다.

### 기호와 심각도

- **▲▼는 증감 전용**이다(`formatDelta`, KpiTile `delta`). '이상 기상 지역', '목표 초과', '주의 구간' 같은 상태 표시에는 쓰지 않는다. 상태는 아래 심각도 아이콘 + 문자를 쓴다.
- **값 칸의 기준·한계·범위 밖 표식은 '!'** 하나로 쓴다. 색은 그 판정의 심각도(경보·주의)를 따르고, 방향(초과·미달)은 열 머리의 한계와 낭독 문구(sr-only "(한계 초과)")로 전한다. ▲▼를 쓰면 대비 대비 증감으로 읽힌다(디자인 개선 도메인 검토 2026-10-30: advancement-decision ▲▼ ↔ phenotype-entry '!').
- **심각도 아이콘은 한 벌**: 경보(critical) = `AlertOctagon` + negative, 주의(warning) = `AlertTriangle` + warning, 달성·정상(ok) = `CheckCircle2` + positive, 정보(info) = `Info` + info. `KpiTile`·`AlertList`가 쓰는 규칙(내부 `severity.ts`)이고, 템플릿이 표·불릿·카드에 심각도를 그릴 때는 `SeverityTag`(@/design-system)를 쓴다. 텍스트 '⚠'·'△'를 심각도 기호로 쓰지 않는다.
- **용어**: critical = '경보', warning = '주의'. '경고'라고 쓰지 않는다. 목록·카드 이름은 '경보·주의 n건'.
- **심각도 테두리는 속삭임**(2026-10-30 C단계): 심각도는 아이콘 + 문자 태그가 말한다. 목록 항목은 중립 1px 테두리 + 왼쪽 2px 심각도 띠(`AlertList`), 타일은 surface 대비 1.1~1.3:1의 옅은 테두리(`KpiTile`)다. 4px 이상 색 띠나 심각도색 전체 테두리(반투명 포함)는 쓰지 않는다. 옅은 심각도 테두리는 반투명(`border-warning/15`)이 아니라 불투명 혼합(`color-mix(… 15%, var(--color-surface))`)으로 쓴다 — 검사 도구가 알파를 버리고 재기 때문이다. 결론 띠(`SummaryCallout`)의 왼쪽 4px 표시는 상자가 아니라 문단 표시라 그대로다.
- **범례 견본 = 차트 마크 모양**: 산점도 채운 원·빈 원, 리드 SNP 다이아몬드, 위반 삼각형, 빗금 막대는 `Legend` `shape`(`circle`·`ring`·`diamond`·`triangle`·`hatch`·`missing`)로 같은 모양을 보인다. 모양을 글자('(채운 원)')로 설명하거나 사각 견본으로 대신하지 않는다(C단계).
- 메타 정보 배지('금액 추정', '목업 값')는 neutral 톤이다. warning 톤은 실제 주의 상태에만 쓴다.

## 갤러리 셸(2026-11-02 리디자인, tasteskill achromatic-ledger · Open plane)

갤러리 크롬은 무채색이다. 색은 템플릿(썸네일 포함)이 가진다. 사이드바는 페이지 바탕 위에 놓이고 캔버스와는 1px 선 하나로 나뉘며 상단 바·블러는 없다(1024 미만만 48px 상단 바 + 메뉴 시트). 사이드바 활성 항목은 **중립 회색 알약**(`--color-active`, 반경 8, 글자색 그대로, `aria-current`)이고 강조색 채움·왼쪽 띠·굵기 변화는 쓰지 않는다. 묶음 라벨은 13px 회색 문장형, 항목은 14/400·32px 높이(34px 간격, 터치·좁은 화면 44px), 개수는 사이드바에 두지 않는다. 목록은 카테고리 구획(h2 16/600 + 회색 개수) 아래 **16:10 썸네일 카드**(1px 테두리·반경 8, 그림자·칩 없음, hover·focus는 썸네일 테두리가 잉크색, 채움은 그대로)이고, 썸네일이 없으면 면 2 색 위에 카테고리 라벨만 둔다(가짜 그림 금지). 셸 글자는 24(h1)/16(h2·카드 제목)/14(본문·nav)/13(메타) 네 단계이고(로고 워드마크 15px만 예외), 강조색은 로고 마크·포커스 링에만, 주 버튼은 「경로 복사」 하나(거의 검정). 쉬는 요소에 그림자를 두지 않고 떠 있는 메뉴 시트·README 패널·토스트만 그림자를 쓴다. 움직임은 시트·패널이 열릴 때 200ms transform·opacity뿐이다. 문구에 em dash를 쓰지 않는다(「·」 「:」).

## 디자인 개선 2차(2026-11-02)

- **결론 우선**: 화면마다 판단 하나가 먼저 읽힌다. 순서는 머리, 결론(`ConclusionPanel` 또는 `SummaryCallout`), KPI, 주 차트, 보조 표다. 어두운 대표 면은 화면당 1개이고 판단이 없으면 쓰지 않는다.
- **구획 표식**: 구획 시작에만 8px 잉크 사각형과 짧은 라벨(`SectionMark`)을 쓴다.
- **저장·확정**: 업무 화면은 `SaveBar` 한 문법(왼쪽 상태 문구, 보조 동작, 오른쪽 주 동작)을 쓴다. 저장은 되돌릴 수 있는 기록, 확정은 되돌리기 어려운 동작이고 확인 절차를 둔다.
- **갤러리 움직임**: 목록 첫 화면 등장 450ms(첫 방문 1회), 스크롤 공개는 `src/gallery/reveal.ts`(진입 직전 1회, 재생 전에는 숨기지 않는다), 시트 240ms, 직접 조작 피드백 120~180ms. KPI 숫자 카운트업과 스크롤 제어는 쓰지 않는다.
- **썸네일**: 1080×675. 큰 카드는 상단 왼쪽 기준으로 자르고 제목·설명은 이미지 밖 불투명 띠에 둔다.

## 레이아웃

- 12열 격자, 간격 16px(모바일 12px), 페이지 좌우 여백 모바일 16px.
- 대시보드 위계: 페이지 머리(`PageHeader`) → KPI 줄(`KpiRow`, 3~5개) → 결론 띠(`SummaryCallout`, KPI 줄 바로 아래 한 곳) → 핵심 차트(가장 큰 영역) → 보조 차트·표.
- **페이지 머리 배치는 하나**: 범위·소속 회색 한 줄 → 제목(24/700) + 오른쪽 기준일 스탬프·필터 → 데이터 한 문장(13 muted) → 「자세히」(긴 정의·규칙 문단을 접어 390px에서 첫 KPI가 화면 안에 들어오게).
- 모바일(390px): 1열, **KPI는 2열**(대표 타일·홀수 마지막 타일은 전체 폭), 차트 높이 240~280px, 표는 가로 스크롤 컨테이너 안에서만 넘침 허용.
- 상세 패널을 옆 카드와 나란히 둘 때는 `self-start`(필요하면 `lg:sticky lg:top-4`)로 늘어나지 않게 한다.
- 인포그래픽은 고정 비율 캔버스(예: 1200×1600, A4 세로)를 쓰고 작은 화면에서는 비율을 유지하며 축소한다. 최소 배율에 걸려 잘리면(768px 포함) 캔버스 위에 요약 카드를 보인다(`ScaledCanvas` `summary`).

## 가로 스크롤 영역

- 넘칠 때만 위에 '옆으로 밀어 … 보기 →' 안내(12px muted, `break-keep`)와 오른쪽 가장자리 페이드를 보인다. 폭 조건(`md:hidden`, `narrow`)이 아니라 **실제 넘침**으로 판단한다(768px에서도 넘치면 보인다).
- 표는 `DataTable`이 기본으로 한다. 표가 아닌 영역(계통도, ADMIXTURE, 격자, 행렬)은 `ScrollRegion`으로 감싼다.
- 페이드는 스크롤 컨테이너의 테두리 안쪽에 그린다(테두리를 덮지 않는다). `DataTable`은 1px 안쪽, `ScrollRegion`은 테두리 두께·모서리 반경을 재서 맞춘다(C단계).
- 결론 열(상태·판정·지수)이 스크롤 끝에 숨지 않게: 좁은 화면에서 덜 중요한 열은 `columns[].hideBelow`로 숨기거나, 좁은 화면용 열 배열에서 결론 열을 앞으로 당긴다(예: `viz/gwas-manhattan` PeakTable).

## 상호작용

- 호버 툴팁: 값 + 단위 + 맥락(예: SNP id, 염색체:위치, p값). 공통 `Tooltip`은 탭(터치)으로도 열리고, 바깥을 탭하면 닫힌다.
- 필터 변경 시 차트 전환 애니메이션 300ms 이하. `prefers-reduced-motion`이면 끈다.
- 포커스 링을 지우지 않는다(키보드 사용자).
- **터치 대상 44px**: 좁은 화면·터치(`(pointer: coarse), (max-width: 639px)`)에서 누를 수 있는 영역을 44px 이상으로 한다. 공통 컴포넌트(Button, Segmented, FilterChip, Switch, Stepper 번호, KpiTile ⓘ, DataTable 정렬 머리·페이지 버튼, 라벨로 감싼 체크박스)는 보이는 크기를 그대로 두고 누르는 영역만 넓힌다(데스크톱 화면 모양은 같다). 템플릿이 직접 만든 작은 버튼·칩에는 `touch-hit`(가로·세로 44px) 또는 `touch-hit-y`(세로만, 붙어 있는 버튼 묶음) 클래스를 붙인다. 인접 대상 사이는 8px 이상 띄운다.
