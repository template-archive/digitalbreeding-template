# 카테고리별 레이아웃 패턴

## kpi — KPI·지표 대시보드

```
│ 벼 · 쌀 수량 · 중부 평야지 프로그램(회색 범위 줄, pill 아님)            │
┌─ 제목(h1) ─────────────── 기준일 2026-10-23  [2022 ▾] – [2026 ▾] ┐  ← PageHeader
│ 데이터 한 문장(기간·범위) · 「자세히」                                │
│ [KPI] [KPI] [KPI] [KPI]                                       │  ← KpiRow, 3~5개, 가장 중요한 것을 맨 왼쪽(hero)
│ ▌결론 한 문장(SummaryCallout, KPI 줄 바로 아래 한 곳)                │
│ ┌──── 핵심 추세 차트 (8열) ─────┐ ┌─ 구성/분해 (4열) ─┐         │
│ └──────────────────────────────┘ └──────────────────┘         │
│ ┌─ 보조 차트 (6열) ─┐ ┌─ 경보·목록 표 (6열) ─┐                   │
└───────────────────────────────────────────────────────────────┘
```

- KPI 카드마다: 값, 단위, 기간, 전기 대비 변화(`better` 방향 반영), 목표·달성 막대. 스파크라인은 두지 않는다(2026-10-30, 추세는 차트로).
- "경보" 영역을 하나 둔다(예: 콜레이트 기준 미달 샘플, Ne < 50 집단). 대시보드는 행동을 유도해야 한다.
- 경보·주의 목록은 공통 `AlertList`(`@/design-system`, KpiTile `severity`와 같은 색·문자 태그)를, 사전 계산 구간 히스토그램의 막대는 `histogramSeries`(`@/charts`)를 쓴다.
- 모바일: KPI 2열(`KpiRow`가 처리) → 결론 띠 → 차트 1열 순서 유지.

## viz — 육종 데이터 시각화

```
┌─ 형질 선택 [수량 ▾]  모델 [GBLUP ▾]  요약: 유의 SNP 7개 · λ=1.03 ┐
│ ┌──────── 주 차트 (맨해튼 등, 12열 또는 8열) ────────┐ ┌ QQ ┐    │
│ └───────────────────────────────────────────────────┘ └────┘    │
│ ┌──── 연동 상세 표 (클릭한 피크·선택 개체) ────┐ ┌ 상세 패널 ┐     │
└─────────────────────────────────────────────────────────────────┘
```

- 주 차트 높이: 데스크톱 360~440px, 모바일 260px.
- 차트 클릭/브러시 → 표·패널 연동이 있어야 "템플릿"으로 가치가 생긴다.
- 요약 줄에 차트의 결론(유의 SNP 수, λ, 설명 분산)을 텍스트로 쓴다. 이것이 곧 `ariaLabel`이다.
- 수백 행 순위 표는 `DataTable`의 `pageSize`·제어형 `sort`/`onSortChange`·`activeRow`로, 파라미터 슬라이더의 눈금·PageUp/Down·aria-valuetext는 `Slider`의 `ticks`·`pageStep`·`valueText`로 한다.
- 0 기준 양방향 막대(선발 차, 표준화 z, 대비 대비 증감)는 공통 `DivergingBar`, 부호 붙은 수(+45, −4)는 `formatSigned`(`@/lib/format`)를 쓴다. 템플릿에 부호 포맷 함수를 따로 만들지 않는다.

## infographic — 인포그래픽·리포트

- 캔버스: `aspect-ratio` 고정(예: 3/4 세로, 16/9 가로), 최대 너비 1200px, 작은 화면에서는 `width:100%`로 축소.
- 구성: 헤드라인(결론 문장) → 큰 숫자 3~6개 → 흐름/비교 시각 요소 → 각주(출처, 기준, "목업 데이터" 표시).
- 아이콘·도형은 SVG 인라인으로 그리고 색은 토큰을 쓴다.
- 장식보다 비교가 먼저: "전통 10년 → 디지털 6년"처럼 전후·대비 구조.
- 인쇄 고려: 인쇄는 화면 테마와 관계없이 라이트 토큰 + 흰 캔버스(공통 규칙, 2026-10-30). 템플릿이 따로 하지 않는다.
- 캔버스가 잘리는 폭(390·768px)의 요약 카드는 `<ScaledCanvas summary={<MobileSummary …/>}>`로 넘긴다.
- 고정 비율 캔버스는 공통 `ScaledCanvas`(`@/design-system`, 크기는 `u(n)`, 인쇄는 `print="a4-landscape"`, 좁은 화면은 `minScale`로 가로 스크롤)를 쓰고 `@media print`·`:has()` 규칙을 템플릿에 직접 쓰지 않는다.
- 표 셀 안 증감 막대는 `DivergingBar layout="inline"`(em 기반)을 `fontSize: u(n)` 요소로 감싸 쓴다.

## workflow — 업무 화면

- 버튼·저장 피드백·단계 표시는 공통 `Button`, `Toast`+`useToast()`, `Stepper`(`@/design-system`)를 쓰고, 표의 열 고정·초기 정렬은 `DataTable`의 `stickyColumn`·`defaultSort`로 한다.
- 머리는 `PageHeader`(방법·용어 설명 문단은 `details`), 요약 줄은 `KpiRow`. 주 동작 버튼은 `Button variant="primary"`(거의 검정), 직접 만든 확정 줄·칩도 강조색 채움을 쓰지 않는다.
- 좁은 화면·터치에서 누르는 것은 44px(공통 컴포넌트 자동, 직접 만든 것은 `touch-hit`). Shift·Ctrl 클릭 전용 다중 선택은 터치 대안(선택 모드 토글 등)을 둔다.

```
┌─ 단계 표시: ① 부모 선택 → ② 조합 검토 → ③ 확정 ───────────────┐
│ ┌ 필터 패널 (3열) ┐ ┌──── 작업 영역 (6열) ────┐ ┌ 선택 요약 (3열) ┐ │
│ │ 형질 범위 슬라이더│ │ 표/행렬/격자             │ │ 선택 항목·경고   │ │
│ └────────────────┘ └────────────────────────┘ │ [확정] 버튼      │ │
└───────────────────────────────────────────────────────────────────┘
```

- 실제로 클릭·선택·해제·확정이 동작해야 한다(로컬 상태).
- 검증 피드백: 입력 범위 오류, 근교도 경고 등은 인라인으로, 저장·확정은 토스트로.
- 표는 `dense` 기본, 키보드로 행 이동·선택 가능하면 가점.
- 모바일에서는 필터 패널을 상단 접이식으로 바꾼다.
