## 가정

- **program-baseline 준수.** 벼(*Oryza sativa*, 12개 염색체, 약 430 Mb, 자식성), 중부 평야지 벼 육종 프로그램의 전용 유전체 분석실이다. 「유전체 분석실(2026)」 표의 값(6K 2,000샘플·TAT 14일, KASP 6.8일, GBS 19.8일, 미해결 재분석 31샘플·6플레이트, 경보 플레이트 KSP-2610-02 Pi9 실패 14.9%·재분석 10/27 예정)을 그대로 쓴다.
- 사용자: 유전체 분석실 담당자(시료 접수·추출·분석 담당 연구원). 하루에 여러 번 열어 어느 플레이트가 어느 단계에 있는지, 무엇이 늦는지, 어느 샘플을 다시 돌려야 하는지 확인하고 상태를 갱신한다.
- 사용 시나리오: 2026-10-23(목) 오후. KSP-2610-06 결과를 오늘 제공했고, KSP-2610-08은 오늘 판독을 마쳐 QC 판정을 기다린다.
- 플랫폼 3개(genotyping-lab-ops와 같음):

| 플랫폼 | 용도 | 시료 | 마커 | TAT 목표 | 2026 평균 TAT |
| --- | --- | --- | --- | --- | --- |
| 6K SNP 칩 | 유전체 선발(GS) 후보 F6 계통 | 계통 잎 | 6,000(QC 후 사용 4,820) | 14일 | 14.0일 |
| KASP 패널 | 마커 보조 선발(MAS) F2 개체 | F2 유묘 잎 | 16 | 7일 | 6.8일 |
| GBS | 교배 부모·훈련 집단 고밀도 보강 | 부모 계통 잎 | 필터 후 약 50,000 SNP(추정) | 21일 | 19.8일 |

- **6K SNP 칩은 진행 중인 플레이트가 없다.** 2026 캠페인(4~7월, 22장, 2,000샘플)이 끝났다. 플랫폼 필터에서 6K를 고르면 빈 상태를 보인다.
- 플레이트: 96웰 1장 = 시료 94 + 대조 2(H11 양성 대조, H12 음성 대조(NTC)). 시료 웰은 행 우선 A01~H10이다.
- 플레이트 ID `KSP-26MM-NN`·`GBS-26MM-01`의 MM은 **결과 제공(예정) 월**이다(genotyping-lab-ops 규칙). 진행 중인 KSP-2610-07~10은 10월 안에 결과가 나올 예정이고(목표 결과일 10/24~10/28), GBS-2611-01은 11/06 예정이다. 번호는 접수 순서와도 일치한다.
- **추적 범위**: 진행 중인 플레이트 5장 + 10월 결과 제공 플레이트 6장 + 미해결 재분석이 남은 9월 플레이트 1장(GBS-2609-01) = **12장, 시료 1,128샘플**(대조 24웰 별도). 검색·플레이트 뷰는 이 범위 안에서 동작한다. 그 이전 플레이트는 "genotyping-lab-ops에서 조회" 안내로 둔다.
- 새로 정한 사실(genotyping-lab-ops에 없던 값, **추정·가상**): 진행 중 플레이트 5장의 단계별 일자, 단계별 마감 기준, 의뢰자·의뢰 번호, KSP-2610-08 판독값, 재분석 시작일 10/22, 정상 웰의 샘플 ID·호출 수, GBS 리드 수, GBS-2611-01의 시료 구성. 의뢰자 이름은 가상이다.
- 처리량 산정은 genotyping-lab-ops와 같이 **결과 제공일 기준**이다. 이 화면의 「10월 결과 제공 564샘플」은 genotyping-lab-ops 10월 처리량 564와 같다.

## 화면 목적과 핵심 질문

1. 지금 어느 단계에 몇 샘플이 있고, 어디가 늦는가? → 진행 중 470샘플(5장). 지연 2장: KSP-2610-07(분석 단계, 1일 지연, PCR 재실시)과 KSP-2610-10(접수 단계, 1일 지연, 동결건조 대기).
2. 다시 돌려야 할 샘플은 몇 개이고 언제 끝나는가? → 미해결 재분석 31샘플·6장. KSP-2610-02 Pi9 14샘플과 KSP-2610-03 2샘플은 진행 중(10/27 예정), KASP 11샘플은 대기(10/30 배치), GBS 4샘플은 재시퀀싱 대기(11/06 예정, GBS-2611-01과 같은 런).
3. 이 샘플(바코드)은 지금 어디에 있고 무슨 일이 있었나? → 검색 한 번으로 플레이트·웰·단계·이력을 확인한다.

### 생성 순서(의사코드, 실행 스크립트와 같음)

```ts
const rng = createRng(SEED)
const usedIds = new Set(FIXED_FAILS.map(f => f.id))
const usedLines = new Set(PARENT_CANDIDATES)
for (const p of PLATES_GEN_ORDER) {             // 생성 순서는 아래 주(화면 표의 접수일 순서와 다름)
  p.stage = lastNonNullIndex(p.dates)           // 0 접수 … 4 결과
  WELLS.forEach((well, idx) => {
    const fx = FIXED_FAILS.find(f => f.plate === p.id && f.well === well)
    // 1) 샘플 ID·계통
    if (p.platform === 'KASP') {
      id = fx ? fx.id : drawUnique(() => `YR25-F2-${pad4(rng.int(1, 400))}-${pad3(rng.int(1, 200))}`, usedIds)
      cross = `CR25-${pad3(Number(id.slice(8, 12)))}`  // 교배 조합 ID, 세대 F2, 개체 = 마지막 3자리
    } else {                                    // GBS
      id = `P-${pad3(p.firstNo + idx)}`         // GBS-2609-01 firstNo 283, GBS-2611-01 firstNo 377
      line = (p.id === 'GBS-2611-01' && idx < 60) ? PARENT_CANDIDATES[idx]
           : drawUnique(() => `YR${rng.int(19, 23)}-${pad4(rng.int(1, 9999))}`, usedLines)
      group = (p.id === 'GBS-2611-01' && idx < 60) ? '부모 후보' : '훈련 집단'
    }
    // 2) 판독값·상태
    if (fx) {                                   // 고정 실패
      status = fx.status; due = fx.date; action = fx.action
      if (KASP) { called = fx.v; call = called / 16 * 100 }
      else { call = fx.v; reads = fx.kind === 'GBS_READS' ? 0.40 + rng.next() * 0.55 : 1.00 + rng.next() * 0.60 }  // 백만 리드
    } else if (p.stage === 4) {                 // 결과 플레이트 통과 웰
      status = '통과'
      if (KASP) { called = rng.next() < 0.88 ? 16 : 15; call = called / 16 * 100 }
      else { call = 100 - (3 + rng.next() * 9); reads = 1.5 + rng.next() * 3 }
    } else if (p.stage === 3 && KASP) {         // QC 단계(KSP-2610-08) 판독값
      const u = rng.next()
      called = u < 0.85 ? 16 : u < 0.96 ? 15 : rng.int(9, 14); call = called / 16 * 100
      status = called <= 14 ? 'QC 실패 예상' : 'QC 판정 대기'
    } else status = `${STAGES[p.stage]} 중`      // 판독 전: RNG 소비 없음
  })
}
```

- **플레이트 순회 순서는 RNG 결과를 바꾼다.** 순서: `GBS-2609-01, KSP-2610-01, 02, 03, 04, 05, 06, 07, 08, 09, 10, GBS-2611-01`(실행 스크립트 순서). 화면 표시 순서(접수일 순)와 다르니 주의한다.
- `drawUnique(f, set)`: `f()`를 set에 없을 때까지 반복해 뽑고 set에 넣는다. KASP는 ID 2개 int를 한 번에 다시 뽑는다.
- 바코드 = `${plateId}-${well}`(예: `KSP-2610-02-E05`). 대조 웰 바코드는 `-H11`·`-H12`이며 검색 결과에서 제외한다.
- 진행 중 플레이트 계산: `elapsed = diff(AS_OF, dates[0])`, `inStage = diff(AS_OF, dates[stage])`, `delay = max(0, elapsed − DEADLINE[platform][stage])`, `targetDate = dates[0] + TAT_TARGET`.
- 재분석 묶음 = 미해결 샘플을 (원 플레이트, 상태)로 묶은 것. 보드 열 = 「단계 보드」 배치 규칙. 기본 상태 묶음 6개: 접수[KSP-2610-04 대기 5, 05 대기 5, 06 대기 1], DNA 추출[KSP-2610-03 진행 중 2], 분석[KSP-2610-02 진행 중 14, GBS-2609-01 재시퀀싱 대기 4].
- 계산값은 모두 이 데이터에서 집계한다(요약 줄·열 머리·플레이트 요약 하드코딩 금지).

### 이력 타임라인 규칙(샘플 상세)

플레이트 일자에서 만든다. 각 이벤트: 날짜, 단계, 설명.

1. 접수 `dates[0]` "시료 접수 · {의뢰 번호} {의뢰자}"
2. DNA 추출 `dates[1]` "DNA 추출 시작"
3. 분석 `dates[2]` KASP "KASP 16마커 PCR·형광 판독", GBS "라이브러리 제작·시퀀싱"
4. QC `dates[3]` "판독 완료 · 콜레이트 {값}" (QC 단계 플레이트는 "QC 판정 대기")
5. 결과 `dates[4]` 통과 "결과 제공 · TAT {n}일", 실패 "QC 실패 · {원인}"

## 상호작용

- **검색**:
  - 바코드·샘플 ID·계통명·교배 조합·플레이트 ID를 대소문자 무시로 부분 일치 검색한다(2글자 이상).
  - 바코드나 샘플 ID가 정확히 하나 맞으면 D(해당 플레이트, 웰 강조)와 E(해당 샘플)로 바로 이동한다.
  - 결과가 여럿이면 결과 표를 보인다.
  - 실행값 예: `KSP-2610-02-E05` → 1건(YR25-F2-0102-014). `YR22-0412` → 1건(GBS-2611-01-A01, P-377, 부모 후보). `YR25-F2-0102` → 4건(KSP-2610-01-H02, KSP-2610-02-E05, KSP-2610-04-E02, KSP-2610-05-B12). 결과가 없으면 "추적 범위(12장)에 없는 샘플입니다. 이전 플레이트는 분석실 운영 현황에서 조회하세요."
- **보드**:
  - 상단 필터: 플랫폼 칩(전체 / 6K / KASP / GBS), "지연만", "재분석만" 토글.
  - 6K를 고르면 EmptyState를 보인다. 제목 "6K SNP 칩은 진행 중인 플레이트가 없습니다 — 2026 캠페인(4~7월, 22장, 2,000샘플) 완료", 설명 "진행 중인 플레이트 없음(2026 캠페인 완료). 다른 플랫폼을 고르거나 「전체」로 돌아가세요."
  - 카드를 클릭하면 D에 그 플레이트를 연다. 재분석 카드는 원 플레이트를 열고 해당 웰들을 강조한다.
  - GBS-2609-01은 9월 결과라 결과 열(10월 제공)에 카드가 없다. 분석 열의 재분석 묶음 카드(재시퀀싱 대기 4)와 D의 플레이트 선택 목록으로만 연다.
  - 카드의 체크박스로 여러 장을 고르면 F가 뜬다. 카드 선택과 웰 선택은 서로 배타적이다(한쪽을 고르면 다른 쪽 선택이 풀린다).
- **플레이트 뷰**:
  - 웰을 클릭하면 E에 상세가 뜬다. Shift·Ctrl 클릭이나 행·열 머리 클릭으로 여러 웰을 고르면 F가 뜬다.
  - 대조 웰(H11·H12)은 고를 수 없다.
  - 툴팁: "E05 · YR25-F2-0102-014 · 15/16(Pi9 미호출) · 재분석 진행 중(10/27 예정)".
- **일괄 작업**(로컬 상태 + 확인 대화상자 + Toast, 저장 지연 600 ms):
  1. **다음 단계로**(플레이트 카드): 접수→DNA 추출, DNA 추출→분석, 분석→QC만 허용한다. 들어간 단계 일자는 AS_OF다. 분석→QC로 옮긴 플레이트는 판독값이 없어 "판독 파일 업로드 대기"로 표시하고 QC 승인을 비활성화한다. 실행값 예: KSP-2610-07을 QC로 옮기면 경과 6 ≤ 7이라 지연이 풀리고, 지연은 1장·94샘플이 된다.
  2. **QC 승인**(QC 단계이고 판독값이 있는 플레이트, 기본 상태에서는 KSP-2610-08뿐): 결과 단계로 옮기고 결과일은 AS_OF(TAT 5일)다. `QC 실패 예상` 웰은 실패가 되어 상태 `대기`, 원인 `KASP_DNA`(미호출 마커 2개 이상(DNA 품질)), 실패일 AS_OF, 예정일 10/30, 조치 "재분석 대기열 등록"으로 바뀐다. 그래서 이후 재분석 시작 시 DNA 추출 열로 간다. 나머지(`QC 판정 대기`)는 `통과`다. 실행값: 결과 열 658샘플·7장, 1차 QC 통과 626/658 = 95.1%, 미해결 재분석 35샘플·7장, 접수 열 재분석 15, 진행 중 376샘플(4장).
  3. **재분석 요청**(웰 선택): `통과` 웰만 가능하다. 사유를 고른다(유전형 의심 · 의뢰자 요청 · 대조 이상). 상태 `대기`, 원인 `REQUEST`("재분석 요청({사유})"), 실패일 AS_OF, 예정일 10/30. 미해결이 선택 수만큼 늘고 접수 열 재분석 묶음에 합쳐진다. `REQUEST` 웰은 QC 실패가 아니므로 1차 QC 통과 수와 플레이트 실패 수·실패율에 그대로 통과로 남는다(1차 QC 통과율은 처음 판정 기준). 재분석 시작 시에는 DNA 품질 원인이 아니므로 분석 열로 간다. 실행값 예: KSP-2610-06 통과 웰 3개 → 미해결 34, 10월 1차 QC 통과 536 그대로.
  4. **재분석 시작**(상태 `대기` 묶음·웰): 상태를 `진행 중`으로 바꾸고, 원인이 DNA 품질이면 DNA 추출 열, 아니면 분석 열로 옮긴다. 예정일은 10/30을 유지한다. 미해결 수는 그대로다(31). 실행값 예: KASP 대기 11을 모두 시작하면 KASP_DNA 9건은 DNA 추출 열, KASP_CLUSTER 2건(KSP-2610-04 D11, KSP-2610-05 C03)은 분석 열로 간다. 재분석 열 값은 접수 0, DNA 추출 2 + 9 = 11, 분석 18 + 2 = 20, 합 31이 된다.
  - 불가능한 선택(대조 웰, 이미 미해결인 웰에 재분석 요청, 결과 플레이트에 다음 단계 등)은 버튼 비활성 + 이유 툴팁.
  - Toast 예: "KSP-2610-08 QC 승인 — 통과 90, 재분석 대기 4".
  - 되돌리기는 마지막 작업 1회만 Toast 버튼으로 지원한다.
- **상태 화면**: `?state=loading|empty|error`.
  - 로딩: 보드 열·격자 자리에 Skeleton을 둔다.
  - 빈 데이터: "추적 중인 샘플이 없습니다"를 띄운다.
  - 오류: "샘플 정보를 불러오지 못했습니다" 문구와 다시 시도 버튼을 둔다.
- **반응형**:
  - 1440px: 보드 5열 가로 배치, 그 아래 D(왼쪽)와 E(오른쪽)를 둔다.
  - 390px: 보드는 열을 세로로 쌓고 각 열을 접을 수 있게 한다(기본은 지연·재분석이 있는 열만 펼침). 격자는 웰 최소 24px로 가로 스크롤 영역 안에 둔다(페이지 가로 넘침 금지).
- **숫자 표기**:
  - 샘플 수는 천 단위 쉼표를 쓴다.
  - 콜레이트는 소수 1자리로 표시한다(KASP는 호출 수 병기).
  - 날짜는 목록에서 MM-DD, 상세에서 YYYY-MM-DD로 쓴다.
- **각주**:
  - "모든 수치·이름은 가상 분석실의 목업 데이터입니다."
  - "단계 마감은 TAT 목표(KASP 7일, GBS 21일, 6K 14일)를 단계별로 나눈 내부 기준입니다."
  - "KASP는 MAS 대상 유전자 마커가 하나라도 미호출이면 실패입니다."
