# 허브 로그인(메일 코드) 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 회사 메일 도메인 직원만 메일 코드로 로그인할 수 있게 한다. 보기 기능은 지금처럼 누구나 쓰고, 로그인 상태는 사이드바에 보인다. 작업 요청 기능이 쓸 `requireUser`·`requireLogin`을 제공한다.

**Architecture:**
- **서버**(`server/auth/`) 계층
  - 순수 규칙(`domain.ts`)
  - 저장소 인터페이스(`store.ts`)와 구현 두 가지: Postgres(`pg-store.ts`), 테스트용 메모리(`memory-store.ts`)
  - 서비스(`service.ts`)
  - 환경 설정(`config.ts`)
  - HTTP 처리기(`handler.ts`)
- **메일**(`mailer.ts`): 발송 방식을 smtp·console 중에서 설정으로 고른다.
- **화면**(`src/features/auth/`): `AuthProvider` 문맥, 로그인 창, 사이드바 계정 영역.
- **공통 정리**: 피드백 처리기의 HTTP 도우미와 쓰기 제한을 공용 모듈로 옮긴다. 쓰기 제한은 분·시·일 창을 받도록 넓힌다.

**Tech Stack:** Node 24(TS 직접 실행), Vercel Node 함수, Neon(`@neondatabase/serverless`), `nodemailer`(새 의존성), React 18, Playwright, `@axe-core/playwright`, `node --test`

**Spec:** `docs/superpowers/specs/2026-11-03-hub-auth-design.md`. 관련 설계는 `docs/superpowers/specs/2026-11-03-hub-requests-design.md`이고, 이 계획은 그 문서의 0단계다.

**브랜치:** `feat/hub-auth`. 설계 문서 커밋이 있는 `feat/hub-requests`에서 갈라졌고, PR 하나로 `main`에 올린다.

## Global Constraints

- 실제 회사 이름·메일 도메인은 저장소 어디에도 쓰지 않는다(코드·테스트·문서·커밋 메시지). 테스트 도메인은 `example.test`, 허용되지 않은 도메인 예시는 `other.test`.
- 인증 환경 변수(`AUTH_ALLOWED_DOMAINS`, `AUTH_SECRET`, `AUTH_DATABASE_URL`, `SMTP_*`, `MAIL_FROM*`)는 서버에서만 읽는다. `VITE_` 접두사를 붙이지 않고, `src/`에서는 참조하지 않는다.
- 운영 비밀은 Production에만 둔다.
  - Production에만: `AUTH_DATABASE_URL`, `SMTP_USER`, `SMTP_PASS`
  - 환경마다 다른 값: `AUTH_SECRET`(Production·Preview)
  - 같은 값: `AUTH_ALLOWED_DOMAINS`
  - 운영(`VERCEL_ENV === 'production'`)에서는 `DATABASE_URL`로도, console 발송으로도 대체하지 않는다.
- 고정 문구(그대로 쓴다)
  - 코드 요청 응답: `코드를 보냈습니다. 메일이 오지 않으면 주소를 확인해 주세요.`
  - 코드 확인 실패(없음·만료·틀림·5회 초과 모두): `코드가 맞지 않거나 만료되었습니다. 코드를 다시 받아 주세요.`
  - 기능 꺼짐: `로그인을 아직 사용할 수 없습니다.`
  - 발송 실패: `코드 메일을 보내지 못했습니다. 잠시 후 다시 시도해 주세요.`
  - 형식 오류: `메일 주소 형식을 확인해 주세요.`
  - 한도 초과: `요청이 많습니다. 잠시 후 다시 시도해 주세요.`
  - 이름 오류: `표시 이름을 1–20자로 입력해 주세요.`
  - 로그인 필요: `로그인이 필요합니다.`
  - 예상하지 못한 서버 오류(DB 등): `로그인 서버에 연결하지 못했습니다. 잠시 후 다시 시도해 주세요.`
- 메일 제목은 `[템플릿 허브] 로그인 코드 {code}`, 보내는 이름 기본값은 `템플릿 허브`다. 본문에는 회사 이름, 도메인, 받는 사람 주소를 넣지 않는다.
- 값
  - 코드: 6자리, 10분 유효, 5회 실패하면 무효
  - 다시 받기: 60초(서버는 같은 주소 분 창 1회)
  - 세션: 사용 없이 30일이면 만료, 처음 만든 뒤 90일이면 만료, 연장 기록은 하루 1번
  - 쿠키: `db_hub_session`, `HttpOnly; SameSite=Lax; Path=/api; Max-Age=7776000`(90일), HTTPS면 `Secure`
- 한도
  - 같은 주소: 분 1·시간 5·하루 10
  - 같은 IP 코드 요청: 시간 20
  - 실제 발송 전체: 하루 300
  - 같은 IP 코드 확인: 분 10
- API 응답에는 메일 주소, 허용 도메인, 가입 여부를 넣지 않는다. 사용자 정보는 `{ id, name }`만 내보낸다.
- API 응답 머리글은 피드백 API와 같다: `Content-Type: application/json; charset=utf-8`, `Cache-Control: private, no-store`, `X-Content-Type-Options: nosniff`. POST는 같은 출처만 받는다.
- 화면
  - 갤러리 셸 규칙(`.claude/skills/db-design-system/references/api-contract.md` 「갤러리 셸·상세 화면」)과 토큰을 따른다.
  - 390·768·1440, 라이트·다크를 모두 지원한다.
  - 터치 영역 44px(`touch-hit`), 글자 11px 이상.
- 피드백 기능(익명)의 동작과 화면은 바꾸지 않는다. 기존 `npm run test:feedback`이 계속 통과해야 한다.
- 새 테스트 파일은 `package.json`의 `test:feedback` 목록에 더한다(Vercel 빌드가 실행).
- 프로세스는 PID로만 종료한다(이름으로 종료 금지).
- 커밋 메시지 끝에는 세션의 공동 작성자 줄을 붙인다.

## Review Focus

1. **코드를 띄어 쓰거나 붙여 넣은 경우**(`123 456`, `123-456`, 앞뒤 줄바꿈): 공백·하이픈을 빼고 확인해야 한다. 테스트는 Task 5에 있다.
2. **다른 탭에서 로그아웃했거나 세션이 만료된 뒤 이름 바꾸기 같은 보호된 동작을 하는 경우**: 401을 받으면 화면이 로그아웃 상태로 바뀌고 로그인 창이 열려야 한다. 테스트는 Task 7에 있다.
3. **Gmail SMTP가 응답하지 않고 멈춘 경우**: Vercel 함수 시간 제한 전에 8초 안에 503으로 끝나고, 저장한 코드는 지워져야 한다. 테스트는 Task 1(메일 시간 제한)과 Task 5(코드 삭제)에 있다.
4. **미리보기 iframe(`?embed=1`)으로 열린 템플릿**: `/api/auth/me`를 부르지 않고 계정 영역도 그리지 않아야 한다. 테스트는 Task 8 화면 점검에 있다.
5. **한글 입력 중 Enter**(표시 이름 칸에서 조합 중인 글자): 조합이 끝나기 전에 제출되면 안 된다. 브라우저 자동화로는 실제 입력기 조합을 재현할 수 없어서, Task 8에서 입력 칸에 조합 중 Enter 차단을 넣고 Task 10에서 폰·PC 한글 입력으로 손 점검한다.

```js
  const mail = loginCodeMail('123456', 'https://hub.example.test')

  const mailer = createSmtpMailer(readSmtpSettings({ SMTP_USER: 'hub@gmail.com', SMTP_PASS: 'x' }), { sendMail: async m => { sent.push(m) } })

  assert.equal(sent[0].to, 'a@example.test')
  assert.match(String(sent[0].from), /템플릿 허브/)

test('a hanging SMTP server fails within the timeout instead of the function limit', async () => {

test('console mailer prints the code for preview and local logins', async () => {
```

### Task 2: 공용 HTTP 도우미와 창 길이를 받는 쓰기 제한

**Files:**
- Create: `server/http.ts`, `server/rate-limit.ts`
- Modify: `server/feedback-handler.ts`, `server/feedback-database.ts`, `server/feedback-domain.ts`
- Test: `tests/http.test.mjs`, `tests/rate-limit.test.mjs`

**Interfaces:**
- Produces(`server/http.ts`)
  - `class HttpError extends Error { readonly status: number; readonly retryAfter?: number; constructor(status: number, message: string, retryAfter?: number) }`
  - `header(request: IncomingMessage, key: string): string`
  - `isSecure(request): boolean`: `VERCEL === '1'`이거나 `x-forwarded-proto: https`
  - `isSameOrigin(request): boolean`: `Origin`이 `{scheme}://{host}`와 같고 `Sec-Fetch-Site`가 `cross-site`가 아님
  - `clientIp(request): string`: Vercel이면 `x-forwarded-for` 첫 값, 아니면 `socket.remoteAddress || 'local'`
  - `readCookie(request, name: string): string | null`
  - `readJsonBody(request, limit: number, messages: { notJson: string; tooLarge: string; invalid: string }): Promise<unknown>`
  - `prepareJson(response): (status: number, value: unknown) => void`: 표준 머리글 세 개를 붙이고 보내는 함수를 돌려준다
- Produces(`server/rate-limit.ts`)
  - `type RateWindow = 'minute' | 'hour' | 'day'`
  - `type SqlQuery = { query(text: string, params?: unknown[]): Promise<Record<string, unknown>[]> }`
  - `RATE_LIMIT_TABLE`(지금의 `feedback_rate_limits` 만들기 문장)
  - `rateBucket(scope: string, key: string, window: RateWindow): string`: `sha256(scope + ':' + window + ':' + key)` hex
  - `countHit(sql: SqlQuery, scope: string, key: string, window: RateWindow): Promise<number>`: 현재 창의 누적 횟수
- 변경
  - `FeedbackError extends HttpError`(생성자 시그니처는 그대로)
  - `limitRequests(key, limit, window: RateWindow = 'minute')`

```js
test('buckets differ by window and scope, never contain the raw key', () => {
  const a = rateBucket('production', 'code-addr:a@example.test', 'minute')
  assert.notEqual(a, rateBucket('production', 'code-addr:a@example.test', 'hour'))
  assert.notEqual(a, rateBucket('preview', 'code-addr:a@example.test', 'minute'))

test('countHit truncates to the requested window and returns the hit count', async () => {
  const calls = []
  const sql = { query: async (text, params) => { calls.push({ text, params }); return [{ hits: 3 }] } }
  assert.equal(await countHit(sql, 'preview', 'k', 'hour'), 3)
  assert.equal(calls[0].params[1], 'hour')
  assert.match(calls[0].text, /date_trunc\(\$2::text, now\(\)\)/)
  await assert.rejects(countHit(sql, 'preview', 'k', 'week'))
})
```

규칙(이 순서로 확인한다):
- **`requestCode`**
  1. 주소 정규화(400)
  2. `hit('code-ip:'+ip,'hour') > 20` → 429
  3. 같은 주소 한도 `code-addr:` 분 > 1, 시간 > 5, 하루 > 10 → 429. 허용되지 않은 주소도 센다.
  4. 허용되지 않은 주소면 아무것도 저장하거나 보내지 않고 `{ resendAfter: 60 }`
  5. `hit('send-global','day') > 300` → 429
  6. 코드 저장(10분)
  7. 발송. 실패하면 `deleteCode` 후 `HttpError(503, MSG_SEND_FAILED)`
- **`verify`**
  1. `hit('verify-ip:'+ip,'minute') > 10` → 429
  2. 주소 정규화(400)
  3. 코드 정규화가 실패하거나, 허용 주소가 아니거나, 코드 행이 없거나, 만료됐거나, 시도가 5번 이상이면 → `HttpError(400, MSG_CODE_FAILED)`
  4. 해시가 다르면 `addCodeAttempt` 후 같은 400
  5. 맞으면 사용자를 찾는다. 없는데 `name`이 없으면 코드를 지우지 않고 `{ needsName: true }`. `name`이 있으면 검증 후 `createUser`
  6. `deleteCode`, `recordLogin`, 세션 생성 → `{ user: {id,name}, token }`
- **`currentUser`**
  - 토큰 모양이 아니거나 세션이 없으면 null
  - `sessionStatus`가 expired면 세션을 지우고 null
  - 사용자 메일이 더 이상 허용 도메인이 아니면 세션을 지우고 null
  - touch면 `touchSession`
- **`rename`**: 로그인하지 않았으면 `HttpError(401, MSG_LOGIN_REQUIRED)`
- **`logout`**: 세션 삭제(없어도 성공)
