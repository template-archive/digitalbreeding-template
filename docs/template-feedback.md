# 템플릿 피드백과 공용 DB

각 템플릿에서 위치를 선택하면 번호 마커와 코멘트 패널이 열립니다. 이름은 선택 사항이며 기본값은 익명입니다. 수정 요청·질문·제안 라벨, 답글, 해결/다시 열기와 원글 작성자의 삭제를 지원합니다.

## 구조

브라우저 → 같은 출처의 `/api/feedback` → Neon PostgreSQL 순서로 저장합니다. Vercel의 Node.js Function과 공식 `@neondatabase/serverless` 드라이버를 사용합니다. 브라우저에는 DB 연결 문자열이나 DB 비밀번호를 보내지 않습니다.

템플릿별 코멘트 문서는 `feedback_pages`의 JSONB와 버전 번호로 저장합니다. 저장 시 현재 버전이 일치하는 경우에만 갱신하고, 충돌하면 최신 문서에서 요청을 다시 적용합니다. 동시에 작성해도 다른 사람의 코멘트를 덮어쓰지 않습니다. 생성·답글 요청은 UUID를 재사용하여 네트워크 재시도에 따른 중복을 방지합니다.

로그인 화면은 없습니다. 서버가 만든 무작위 익명 쿠키(HttpOnly, SameSite=Lax, 운영에서는 Secure)로 브라우저를 식별합니다. DB에는 쿠키 원문 대신 SHA-256 식별자를 기록합니다. 삭제 권한은 서버가 검증하며 클라이언트가 전달한 작성자 ID나 작성 시각을 신뢰하지 않습니다. 라벨과 해결 상태는 모든 방문자가 변경할 수 있습니다.

이름은 인증되지 않은 표시 이름입니다. 쿠키를 지우거나 다른 브라우저·다른 도메인으로 이동하면 예전 글의 삭제 권한을 복구할 수 없습니다. 사내 사용자는 하나의 운영 도메인을 사용하세요. 로그인 없는 작성 기능은 사이트 접근 제한을 대체하지 않습니다.

## DB 연결

1. Vercel 프로젝트 Storage에서 Neon을 생성하고 프로젝트에 연결합니다.
2. Production과 Preview 환경에 서버 환경 변수 `DATABASE_URL`이 연결되어 있는지 확인합니다. `POSTGRES_URL`도 대체 값으로 지원합니다.
3. 새로 배포합니다. 첫 API 요청에서 `db/feedback-schema.sql`과 같은 테이블을 멱등하게 생성합니다. 초기화도 트랜잭션 잠금을 사용합니다.
4. 별도 브라우저에서 같은 템플릿의 코멘트를 조회하고 답글을 남겨 공유를 확인합니다.

로컬 개발은 `.env.example`을 참고하여 `.env.local`에 서버 연결 문자열을 설정한 뒤 `npm run dev`를 실행합니다. Vite의 개발용 API도 같은 서버 핸들러를 사용합니다. 값에 `VITE_` 접두어를 붙이지 마세요. 실제 비밀번호는 Git에 포함하지 않습니다.

운영 데이터는 `production`, 미리보기는 `preview:<git branch>`, 로컬은 `preview:local` 범위로 분리합니다. Neon의 Preview DB branch 기능과 함께 사용할 수 있습니다. 미리보기 DB의 수명·복제 정책은 Neon/Vercel 연결 설정을 따릅니다.

## 동기화 및 실패 처리

하단 피드백 도구를 연 동안 15초마다 새 코멘트를 확인하며 창으로 돌아올 때도 갱신합니다. 저장 요청은 중복 제출을 막고 처리 중 상태를 표시합니다. 네트워크·DB 오류에서는 작성 내용을 지우거나 로컬 저장을 공유 저장으로 표시하지 않습니다. 연결이 끊겨도 화면에 남은 코멘트는 유지합니다.

기존 localStorage 코멘트는 삭제하거나 자동으로 서버에 업로드하지 않습니다. 이전 브라우저 저장 버전에서 작성한 데이터는 기존 저장 키에 남아 있으며, 공용 저장소의 코멘트와는 별개입니다. 표시 이름만 브라우저에서 선택적으로 기억합니다.

## 위치와 접근성

마커는 요소 경로와 내부 상대 좌표를 저장합니다. 대상이 사라지거나 글자가 달라지면 다른 영역에 붙이지 않고 목록에 위치 없음 안내를 표시합니다. 대상이 복원되면 마커도 다시 나타납니다. 미리보기 iframe의 패널은 바깥 화면에 띄워 아래에 가려지지 않게 합니다. Esc 닫기, Ctrl/Cmd+Enter 제출, 키보드용 페이지 전체 코멘트와 모바일 하단 패널을 지원합니다. 인쇄에는 피드백 UI를 표시하지 않습니다.

업로드한 업무 데이터 미리보기에는 코멘트를 붙이지 않습니다. 기본 목업 템플릿에만 적용하며 선택 영역의 글자 일부(최대 100자)는 위치 확인용으로 코멘트와 함께 저장합니다.

## 제한 및 검증

템플릿당 500개 스레드, 스레드당 100개 메시지, 메시지당 2,000자, 템플릿 문서당 2MiB로 제한합니다. 요청 본문은 20KB입니다. 서버는 `server/feedback-templates.ts` 목록에 있는 템플릿만 받습니다. 이 목록은 `src/templates` 폴더에서 생성합니다. 템플릿을 추가·삭제하면 `npm run sync:feedback-templates`를 실행하고 결과를 함께 커밋합니다. 목록과 폴더가 다르면 `npm run test:feedback`(빌드에 포함)이 실패합니다.

익명 작성자당 분당 쓰기 30회, IP당 분당 쓰기 180회와 전체 API 300회로 제한합니다. 원본 IP 대신 해시한 제한용 키만 저장하고 오래된 키는 정리합니다. 출처와 JSON 형식을 확인하고, SQL에는 매개변수를 사용하며, 코멘트는 HTML로 실행하지 않고 텍스트로 표시합니다.

`npm run test:feedback`은 데이터 검증·기존 저장 데이터 보존, 익명 작성자 위조 방지, 삭제 권한, 중복 요청, 해결된 글의 답글 제한과 API 입력 경계를 검사합니다. `npm run build`에 이 테스트와 프런트·서버 TypeScript 검사를 포함합니다.

## 검토 도구 UX

기본 화면에는 작은 하단 런처만 표시합니다. 도구를 열기 전에는 코멘트 API를 조회하거나 자동 갱신하지 않습니다. 도구를 접으면 자동 조회를 멈춥니다. 위치 코멘트 모드는 C, 닫기는 Esc를 지원하며 입력 필드·한글 조합·브라우저 단축키에서는 C를 가로채지 않습니다.

위치 선택 중에는 대상을 강조합니다. 핀 숨기기와 보관함 열기는 독립적으로 동작합니다. 보관함은 현재 템플릿 범위이며 내용·답글·작성자·라벨을 검색하고 상태로 필터링합니다. 선택한 스레드의 이전/다음 버튼은 현재 검색·필터 결과를 따릅니다.

코멘트 링크를 복사하면 같은 템플릿과 스레드를 바로 여는 주소를 얻습니다. 임베드나 접근 우회 같은 페이지 매개변수는 공유 링크에 복사하지 않습니다. 클립보드를 사용할 수 없으면 선택 가능한 주소 입력란을 제공합니다. 없는 코멘트 링크는 삭제되었거나 다른 배포 범위일 수 있음을 안내합니다.

새 코멘트/답글 표시는 마지막으로 열어 본 메시지 ID와 현재 익명 작성자를 비교합니다. 읽음 상태와 도구의 좌우 배치만 브라우저에 기억하며 공용 DB 데이터와 분리합니다. 로그인이나 이메일 알림 기능은 추가하지 않습니다. 브라우저 저장을 사용할 수 없어도 공용 코멘트 작성은 동작합니다.

참고한 패턴: [Vercel Toolbar](https://vercel.com/docs/vercel-toolbar), [Using Comments](https://vercel.com/docs/comments/using-comments).

패널이 키보드 포커스를 받은 페이지 조작을 완전히 가리면, 입력 중인 초안은 유지한 채 패널만 최소화합니다. 도구의 코멘트 버튼으로 같은 초안을 다시 열 수 있습니다. 320px 화면에서도 도구의 조작 영역이 경계 안에 들어가게 배치합니다.
