# LD 구조

- 카테고리: viz · 작물: 벼 · 시드 20261023
- 명세: `docs/specs/ld-decay.md`

## 목적
GWAS 패널(YR 다양성 패널 412계통, 36,420 SNP)에서 LD가 몇 kb에서 r² = 0.2 아래로 떨어지는지 하위 집단·염색체별로 비교하고,
gwas-manhattan 유의 피크 구간(리드 ± 500 kb)의 LD 블록·리드 SNP 프록시로 파인 매핑 범위를 정한다.

## 화면 구성
- KPI: 패널 전체 d₀.₂(염색체 선택 따름) · 하위 집단 범위와 배율 · 선택 구간 블록 수 · 리드 SNP 블록(단형/블록 밖 표기)
- LD 히트맵(Haploview형 45° 삼각형, r² 연속 순차 척도, 블록 외곽선, 단형 SNP 빗금, 위치 트랙·QTL 괄호·후보 유전자 눈금) + 블록 목록
- LD 감소 곡선(10 kb 구간 평균 + 적합 r² = b + a/(1 + d/h), r² = 0.2 기준선·교차 라벨, 쌍별 점 스위치)
- 염색체별 d₀.₂ 점 그림, 집단 비교 표, GWAS 피크 구간 바로 가기 표(행 클릭·Enter)
- 개발용 상태: `?state=loading|empty|error`

## 사용 지표
r²(0/1 근교계 유전형), LD 감소 거리 d₀.₂, 반감 거리 h, 근거리 r²(0~10 kb), 배경 r²(비연관 쌍)와 1/n 대비 배율,
r² 스파인 블록(첫·끝 SNP가 블록 안 모든 SNP와 r² ≥ 0.5, 3 SNP 이상), 프록시 SNP(r² ≥ 0.8).

## 실제 데이터로 교체하기
`data.ts`의 `computeAll()`이 돌려주는 `LdData`(감소 곡선 집계 `DecayResult`, 프리셋 창 `PresetWindow[]`, 집단별 분석 `PresetView[][]`)
형태만 맞추면 화면은 그대로 동작한다. 실제 서비스에서는 r² 계산(PLINK `--r2` 등)을 서버에서 하고 구간 평균·적합값과 창별 r² 행렬만 받는 편이 낫다.
목업 계산(72창 + 12창, 비트셋 popcount)은 마운트 후 한 번 수행하고 그동안 Skeleton을 보인다.
`data.ts` 끝의 DEV 검산(`[검산]` console.assert)이 명세 수용 기준 숫자를 확인한다.
