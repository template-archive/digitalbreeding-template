# 계통 진급 심사

- 카테고리: workflow · 작물: 벼(가상 중부 평야지 프로그램)
- 명세: `docs/specs/advancement-decision.md`

## 목적
2026 생산력 검정(AYT, 시험포장 A-3) 성적으로 2027 지역 적응 시험(MET)에 올릴 계통을 고르는 진급 심사 초안 화면이다. 필수 형질 한계 → 수량 지수 → GEBV 보완 순서의 자동 판정과 비교하며 계통마다 진급·보류·탈락을 정하고, 기준과 다른 결정에는 사유를 남겨 저장한다.

핵심 질문: 진급 목표 18계통까지 얼마나 왔나(진급 9 / 목표 18, 예상 15) · 더 볼 계통은(보류 권고, 수량은 높은데 필수 형질 위반, GEBV 낮음) · 기준과 다른 결정에 근거가 있나(3건, 사유 3/3).

## 사용 지표
쌀 수량(정상 관측 구 평균, kg/10a) · 대비 품종 대비 지수(가람솔 A-3 = 100) · 출수기 · 간장 · 잎도열병 발병 지수 · 밥맛(식미치) · 수량 GEBV·신뢰도(r²) · 진급 지수(수량 지수 35% · GEBV 15% · 간장 15% · 도열병 20% · 밥맛 15%, 정렬용) · 종자 재고(MET 출고 600 g 후 최소 보유 500 g).

## 구성
- `data.ts`: field-trial-layout 생성 규칙 복사(1~5단계) + 같은 rng로 도열병·밥맛·GEBV·신뢰도(6단계) + 판정·진급 지수·종자(7단계), 저장된 결정 20건, `summarize`·`applyRecommendations`, DEV 검산(`[검산]`).
- `components/CriteriaCard` 판정 기준 · `IndexGebvScatter` 지수×GEBV 산점도 · `LineTable` 필터·표·390px 카드 · `LineDetail` 상세·결정 입력 · `DecisionSummary` 결정 요약 · `ui` 배지·형질 셀·필터 칩·결정 토글.
- `qa-states.json`: 사유 오류, 사유 저장, 저장된 기준과 다른 결정 상세, 필터 2종, 일괄 자동 판정.

## 실제 데이터로 교체하기
`LINES`(계통별 성적·GEBV·종자 재고)를 API 응답으로, `SAVED_DECISIONS`를 저장된 결정으로 바꾼다. 판정 기준 상수(`LIMITS`, `Y_PROMOTE`, `Y_HOLD`, `GEBV_RESCUE`, `WEIGHTS`)는 프로그램 내부 기준으로 교체한다. 저장은 `save()`의 `setTimeout`을 API 호출로 바꾼다.
