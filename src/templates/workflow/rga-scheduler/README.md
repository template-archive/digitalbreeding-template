# 속성세대진전 일정

- 카테고리: workflow
- 명세: `docs/specs/rga-scheduler.md`

## 목적
속성세대진전(RGA) 온실 2동 10베드에서 묶음(1묶음 = 1베드)별 세대 일정(파종·출수·수확·정리)을 간트로 보고, 다음 세대의 파종일·베드·세대 단축 방법을 고쳐 수용량·정비 충돌과 GS 1차 시료 채취 마감을 확인한 뒤 저장한다.

## 화면 구성
- KPI 4칸(390px는 `MobileSummary`): 베드 점유(hero), 세대 진전 속도, 2027 GS 1차 시료 채취, 2027년 1차 교배 부모 파종 D-day
- 경보·주의(`AlertList`) + 정보 목록(`AlertList` severity `info`, 2026-10-30 공통화)
- 셀 점유 추이(ECharts 누적 영역, 주별 62점, 수용량선·오늘선)
- 베드 간트(HTML/CSS, `components/BedGantt.tsx`): 베드 10행, 묶음이 둘인 베드는 레인 분리, 오늘·GS 마감선·2027 교배 띠, 정비 빗금, 미저장 미리보기 점선, 충돌 빗금
- 묶음 표(`DataTable`, 390px 카드) + 묶음 상세·편집 / 베드 상세 패널, `SaveBar`, 토스트

## 사용 지표
세대당 일수(95/85일), 연간 세대 수(3.8), F1→F6 종자 기간(475일 = 1.3년), 세대 간격 L 2.2년(설계값), 베드 점유·셀 점유율, 향후 90일 평균 점유율, GS 1차 시료 채취 여유, 교배 부모 첫 파종 D-day, 베드 충돌.

## 실제 데이터로 교체하기
- `BATCHES`(묶음), `P27`·`P26`(교배 부모), `MAINT`(정비), `DEADLINE_GS`, `METHOD`를 API 응답으로 바꾼다.
- 일정 계산(`schedule`, `buildPlan`, `validate`, `summarize`)은 순수 함수라 그대로 쓴다. 저장(`save`)은 로컬 상태 + 600 ms 지연이므로 API 호출로 바꾼다.
- `data.ts` 끝의 DEV 검산은 명세 실행값(점유 3,396셀, 여유 120…33일, 충돌 시나리오 문구 등)을 확인한다.

## 상태 화면
`?state=loading|empty|error`. QA 상태는 `qa-states.json`(8개).
