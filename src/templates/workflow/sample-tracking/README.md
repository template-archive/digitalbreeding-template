## 목적
유전체 분석실 담당자가 하루에 여러 번 열어 본다.
1. 지금 어느 단계에 몇 샘플이 있고 어디가 늦는가(단계 보드, 지연 배지)
2. 다시 돌려야 할 샘플은 몇 개이고 언제 끝나는가(재분석 묶음 카드, 예정일)
3. 이 바코드는 지금 어디에 있고 무슨 일이 있었나(검색 → 96웰 플레이트 뷰 → 샘플 상세 이력)

그리고 단계·재분석 상태를 바꾼다: 다음 단계로, QC 승인, 재분석 요청, 재분석 시작. 모두 확인 대화상자를 거쳐 600 ms 저장 지연 뒤 토스트로 알리고, 마지막 작업 1회는 토스트의 「되돌리기」로 되돌린다.

## 사용 지표
단계별 샘플 수, 경과일·단계 마감·지연, 목표 결과일, TAT, 샘플 콜레이트(call rate), 플레이트 평균 콜레이트·실패율(경보 > 10%), 10월 1차 QC 통과율, 미해결 재분석 수. 정의는 명세 「지표 정의」와 `breeding-metrics` 카탈로그 4장.

## 실제 데이터로 교체하기
- `PLATES`(플레이트 메타·단계 일자 `[접수, 추출, 분석, QC, 결과]`)와 `INITIAL_SAMPLES`(웰 단위 판독값·상태)를 LIMS 응답으로 채운다. 모양만 맞추면 `buildBoard`·`buildSummary`·`plateStats`·`sampleTimeline`·`searchSamples`가 그대로 동작한다.
- 일괄 작업 함수(`advancePlates`·`approveQc`·`requestRerun`·`startRerun`)는 새 `TrackState`를 돌려주는 순수 함수다. 서버 저장으로 바꿀 때는 `index.tsx`의 `commit()`에서 API를 부르고 응답으로 상태를 교체한다.
- 기준일 `AS_OF`는 실제 화면에서는 오늘 날짜로 바꾼다.
- 개발용 상태 화면: `?state=loading|empty|error`.

## 구현 메모
- `data.ts` 끝의 DEV 검산(`console.assert` + `[검산]`)이 수용 기준 숫자를 확인한다: 1,128샘플·ID 고유, 470/2장·188/31·6장·경보 1/564·536, 보드 94/94/188/94/564, 재분석 11/2/18/0, KSP-2610-02 실패 14·평균 98.1·16/16 66·15/16 14, 08 QC 실패 예상 4, 10월 실패 수·TAT, 검색 예시, QC 승인 후 658·626·35·7장·접수 재분석 15·진행 376, 재분석 시작 후 0/11/20/0, KSP-2610-07 QC 이동 후 지연 1장.
- 선택 규칙: 카드 선택과 웰 선택은 서로 배타적이다(한쪽을 고르면 다른 쪽 선택이 풀린다). 「여러 웰 선택」을 켜면 수정자 키 없이 웰을 누를 때마다 선택·해제되고(샘플 상세는 그대로), 끄면 누름 = 샘플 상세. Shift·Ctrl 클릭과 Shift+Enter는 모드와 관계없이 다중 선택이다.
