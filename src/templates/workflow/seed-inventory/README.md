# 종자 재고·분양

- 카테고리: workflow · slug `seed-inventory`
- 명세: `docs/specs/seed-inventory.md` (기준일 2026-10-23, 시드 20261023)

## 목적

종자 관리 담당자와 육종 연구원이 하루에 몇 번 열어 다음 세 가지를 처리한다.

1. 들어온 분양·반출 요청을 점검해 승인·반려·출고한다(차단 사유가 있으면 승인·출고 불가).
2. 최소 보유량에 못 미치거나 쓸 수 없는 계통(발아 불합격·소진·사용 보류·입고 대기)을 찾는다.
3. 발아 재검사 기한이 지났거나 30일 안에 오는 로트를 확인한다.

## 사용 지표

로트·재고량(정조 g, F1 립), 립 환산(g ÷ 천립중(정조) × 1,000), 천립중(정조), 발아율·판정(합격 ≥ 85 · 주의 80~84 · 불합격 < 80), 재검사 기한(+12/+6개월), 로트 상태, 계통 가용 재고, 최소 보유량 미달, 요청 상태·점검 차단·10월 출고. 정의는 명세 「지표 정의」.

## 실제 데이터로 교체하기

- `data.ts`의 `BASE_LOTS`(로트 + `tests` + `events` 원장)와 `REQUESTS`를 API 응답으로 바꾼다. 재고는 저장하지 않고 원장(`balance`)에서 계산한다.
- `derive`·`evalItem`·`evalRequest`·`summarize`·`isAlarmLot`·`ship`·`approve`·`reject`·`setMta`·`updateItem`은 순수 함수라 그대로 쓴다. 저장은 `ship`이 돌려준 새 상태 대신 서버 호출로 바꾼다.
- 기준값(`MIN_HOLD`, `GERM_PASS`·`GERM_FAIL`, `RETEST_MONTHS`, `STD_OUT`, 저장 조건)은 내부 기준(추정)이므로 기관 기준으로 교체한다.
- 개발용 상태 화면: `?state=loading|empty|error`.
